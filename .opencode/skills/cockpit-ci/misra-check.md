# MISRA C/C++ 规范审查（智能座舱子集）

## 强制检查规则（自动拦截）

| 规则 | 描述 | 检查要点 |
|------|------|---------|
| **Rule 1.1** | 代码不得包含未定义或未指定行为 | 检查数组越界、空指针、有符号溢出 |
| **Rule 8.2** | 函数必须有原型声明 | 所有函数在使用前必须有声明 |
| **Rule 8.7** | 非外部链接对象应在文件内部使用 | 检查 static 关键字使用 |
| **Rule 10.1** | 不得对布尔类型进行算术运算 | 检查 if(flag == 1) 等写法 |
| **Rule 10.3** | 整型表达式不得隐式转换为更窄类型 | 检查赋值时的类型隐式转换 |
| **Rule 11.5** | 不得将指向 void 的指针转换为指向对象的指针 | 检查 malloc 返回值的使用 |
| **Rule 12.1** | 表达式的优先级应明确 | 建议用括号明确优先级 |
| **Rule 14.3** | 控制表达式应是布尔类型 | 检查 while(p) 应写为 while(p != NULL) |
| **Rule 15.1** | goto 语句不得使用 | 检查 goto 出现 |
| **Rule 16.3** | switch 的每个 case 必须用 break 终止 | 检查 case 穿透 |
| **Rule 17.2** | 函数不得直接或间接调用自身 | 检查递归调用 |
| **Rule 18.1** | 不得使用动态内存分配 | 检查 malloc/calloc/realloc/free |
| **Rule 18.4** | 不得使用 setjmp/longjmp | 检查 setjmp/longjmp |
| **Rule 19.1** | assert 不得用在生产代码 | 检查 assert 使用 |
| **Rule 20.1** | #include 指令后只跟文件标识符 | 检查 #include 写法 |
| **Rule 21.10** | 不得使用 stdlib.h 中的 atoi/atof/atol | 推荐用 strtol/strtof |
| **Rule 22.1** | 动态分配的对象必须显式释放 | 检查内存释放路径 |

## 座舱安全关键规则（功能安全 ISO 26262）

- ASIL-B 级代码禁止使用动态内存分配（Rule 18.1 严格化）
- 所有指针参数必须加 `_In_` / `_Out_` SAL 注解
- 错误路径必须有明确的错误码返回，不得静默忽略
- 中断服务例程（ISR）中不得调用非确定性函数
- 共享数据必须用原子操作或互斥量保护

## 检查指令

当被要求做 MISRA 检查时：
1. 列出所有的 MISRA 违规行，按严重度排序
2. 对每条违规，标注违反的规则编号
3. 给出修复建议
4. 对座舱安全关键代码加注 `[SAFETY-CRITICAL]` 标记
